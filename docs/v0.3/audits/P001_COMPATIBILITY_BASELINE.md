## Compatibility invariants to preserve

| Contract | Observed invariant | Evidence / compatibility consequence |
|---|---|---|
| HTTP version and wire paths | Product resources are under `/api/v1`; unversioned `/live`, `/ready`, `/health/live`, `/health/ready` are deployment probes. | `crates/api/src/router.rs`, `api/openapi.yaml`. Additive changes must not silently repurpose v1 paths/meanings. The OpenAPI `info.version=0.1.0-blueprint` differs from product source version and needs explicit reconciliation. |
| Browser identity | Browser session token is random, not its record ID; only a digest persists. Production cookie is host-only/HttpOnly/Secure with SameSite policy. Mutations use session-bound CSRF and provenance validation. | `crates/auth/src/sessions.rs`, `crates/api/src/cookies.rs`, `crates/api/src/csrf.rs`. Preserve cookie name/scope/session lifetime and CSRF behavior for existing web clients. |
| Device identity and enrollment | Device bearer is a separate principal bound to owner, Device and credential; one-time grant is consumed once; credential storage is digest-only server-side and revoked credentials are checked. | `crates/api/src/device_auth.rs`, `crates/auth/src/device_credentials.rs`, migration `20260828000000_device_credentials_enrollment.sql`. Do not reinterpret browser sessions as device credentials or rebind a stored identity to another origin/owner/device. |
| Resource access | Node, version, library, backup and sync operations are owner-scoped; device sync additionally binds a registered Device and Library. Opaque IDs and client-side profile labels do not grant authorization. | API handlers, metadata repositories and foreign keys. Keep ownership checks server-side and preserve existing owner-only access semantics. |
| Canonical storage | PostgreSQL stores logical metadata; canonical bytes are held by the ObjectStore adapter behind opaque server-only keys and integrity/length expectations. File versions are immutable. | `crates/storage`, `crates/object-store`, `crates/metadata`, upload/download routes. Preserve the metadata/content boundary and avoid changing existing object layout/identity without an explicit migration. |
| File/version operations | Historical restore creates a new immutable FileVersion referencing verified content; it does not rewind history or expose physical storage details. | `crates/api/src/versions.rs`, restore migrations and OpenAPI. Preserve existing version identity and history behavior. |
| Sync ordering and acknowledgement | Feed order is library epoch/sequence; device checkpoints are independent per Library. Acknowledgement evidence advances only after bounded delivery verification and durable local application. Snapshot/rebaseline transfers logical metadata, not object bytes. | `migrations/README.md`, sync/rebaseline API and client SQLite migrations. Do not weaken order, replay/idempotency, snapshot handoff or restart recovery. |
| Mutation/conflict semantics | Client mutations use stable mutation IDs/fingerprints and explicit revision/base preconditions; conflicts persist; resolution is explicit/manual. No last-write-wins or automatic merge. | `/api/v1/devices/{device}/libraries/{library}/mutations` and `/conflicts`. Preserve fail-safe stale-write behavior and conflict evidence. |
| Local persistence | Desktop, Android and iOS each hold independent local profiles/queues/projections; local schema migration must preserve queued intent, checkpoints, transfer state and credential bindings. Secret material remains in OS secret stores/Keystore/Keychain, not general SQLite/profile JSON. | `crates/client-sync/migrations`, Android Room/DataStore, iOS SQLite/Keychain code. Never reset or infer identity from Library IDs when migrating. |
| Offline/error recovery | Ambiguous mutations are reconciled against authoritative state; browser auth recovery does not replay POSTs; interrupted installation recovery inspects ownership/journal state before retry. | Web session coordinator, sync/installer state machines. Keep retry behavior idempotent and fail closed on unknown outcomes. |
| Network transport | Production mobile profiles require HTTPS; debug cleartext exception is numeric loopback only. Existing operator HTTPS and managed local/LAN TLS behavior must remain available; Tailscale is currently excluded from LAN candidates as a tunnel. | Android/iOS endpoint validation and `synveil-server-network`. Preserve LAN semantics and avoid treating a tunnel interface as a managed public LAN adapter. |

## Compatibility gaps and unknowns

* No supported v0.2 server/client version pair or minimum-client policy is published. **`UNKNOWN`**.
* No live server compatibility run for exact Android/iOS release artifacts and no signed mobile artifact was found. **`BLOCKED`**.
* Web browser/version support is unspecified. **`UNKNOWN`**.
* macOS desktop release support is absent from the v0.2 target matrix. **`NOT_APPLICABLE`**.
* The OpenAPI `info.version` is stale relative to product version; code still mounts `/api/v1`. Do not infer a v2 wire contract from the product's v0.2 label.
* Existing file upload/download, sync, backup and recovery implementations span different clients; CI checks do not prove every client interoperates with every deployed server version.
