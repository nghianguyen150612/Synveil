# Troubleshooting Synveil v0.2

> v0.2 is upcoming, not released. These are the safe actions for the planned installer and first-run flow. For the current product, use the v0.1 [operations](../RELEASE_OPERATIONS.md), [package](../RELEASE_PACKAGING.md), and [upgrade-safety](../UPGRADE_SAFETY.md) guides.

For support, note the product version, operating-system version, architecture, the action you were taking, the exact safe error text, and any support reference shown by Synveil. Do not send passwords, one-time codes, tokens, database addresses with credentials, private keys, personal file names, or unrestricted screenshots. Synveil does not upload diagnostics automatically.

| What happened | Check | Safe recovery | Seek support when |
| --- | --- | --- | --- |
| **Unsupported operating system** | Compare the exact OS name and version with the release's support list. | Stop. Use a listed OS; do not change the OS identity or bypass the platform check. | Your exact version is listed but Synveil rejects it. |
| **Unsupported architecture** | Confirm the computer is x86_64; the v0.2 target does not include ARM64/aarch64 or 32-bit systems. | Get only an artifact built for a listed architecture. If none exists, wait for support. | The release lists your architecture but rejects it. |
| **Download failure** | Check network access, available storage, and whether the official release source is reachable. | Start a fresh download from the published official entry. Retry only while setup has not begun changing the installation. | A fresh download repeatedly fails. |
| **Artifact integrity failure** | Check that you used the exact release file and its matching trusted verification instructions. | Do not open or install the file. Discard that downloaded copy and obtain fresh bytes from the official release entry; verify again. Never bypass verification. | A fresh official file also fails verification. |
| **Insufficient disk space** | Check free space using your operating system's storage view. | Free space in locations you own, then follow the installer or native package manager's stated recovery step. Do not delete Synveil state, libraries, or database files. | Space is available but installation still reports the error, or mutation may have started. |
| **Missing authorization** | Check whether the native package application or Setup is waiting for permission. | Approve only the visible, expected OS prompt with an account allowed to install software. Otherwise cancel and ask the device administrator. Do not run Synveil as administrator or root. | The prompt is unexpected, absent, or the authorization is rejected. |
| **Installation failure** | Note the platform's error and whether the native installer says it made changes. Check whether another package operation is active. | Use the named Repair or native package-manager recovery path. If the result is uncertain, inspect/reconcile first; do not force or repeat a mutation. | Repair is unavailable, the native manager reports an unresolved transaction, or the error repeats. |
| **Interrupted installation** | Determine whether Setup or the native package manager offers a recovery message. | Follow that named recovery flow. If state is unclear, stop and use supported Repair/recovery before another install attempt. | Recovery cannot establish whether installation completed. |
| **Recovery required** | Read the message for the named check or repair action. | Let Synveil or the native package manager reconcile the prior operation. Keep its recovery evidence; do not delete journals or replay the install blindly. | Reconciliation stops, reports unknown state, or asks for administrator support. |
| **Existing installation conflict** | Check the installed version and the OS package application's registered Synveil entry. | Use the existing installation's supported same-version repair or compatible upgrade path. Do not install a different package over an unknown installation. | Ownership or version cannot be identified safely. |
| **Runtime dependency problem** | Check whether your OS version is on the release's exact support list and whether the release lists a missing system requirement. | Install system updates only through the OS vendor's normal tools, then use the documented Repair path. For an unsupported AppImage runtime, use a qualified package or wait; do not fetch libraries from an untrusted site. | The listed environment is current and Repair still fails. |
| **First-run connection failure** | Check the server address, DNS/network, server readiness, and HTTPS certificate. | Restore server/network access or ask the server administrator to check availability and TLS. Then use Connect again. Never disable TLS verification. | The address is correct and the server is reachable but Synveil still cannot connect. |
| **Authentication failure** | Check that the server issued a current one-time device code and that the account can sign in. | Request a new code through the server's supported flow and enter it only in Synveil. Do not send codes or credentials to support. | A fresh code is rejected or the sign-in result is uncertain. |
| **Initial synchronization does not start** | Confirm the server and sign-in stages are ready, the library is configured, the local folder is available, sync is not paused, and no attention item is waiting. | Reconnect the folder or server using the app's named action. Select **Sync** if it is offered for that library. Resolve conflicts using the app's supported workflow; preserve local files. | The folder and connection are ready but sync remains stopped or repeatedly asks for attention. |

An incomplete setup may be safe to continue only through the action the app or native manager names. A verified download is not proof of installation, and installation is not proof of synchronization.
