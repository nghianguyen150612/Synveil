# ADR-058: v0.2 Debian/Ubuntu desktop package UX

Status: **Accepted — Prompt013 contract**
Date: 2026-09-29
Decision owners: Synveil maintainers

## Context

Synveil already produces a native DEB, but v0.2 needs a clear ordinary desktop
installation path without a second installer or terminal-only repair steps.

## Decision

The versioned DEB is the primary Debian/Ubuntu x86_64 artifact. The desktop's
native graphical package application is the installer UI, while APT/dpkg owns
authorization, dependencies, package files, and transactions. Synveil adds no
package wizard. The launcher directly executes `/usr/bin/synveil-desktop` as
the signed-in user. Installation neither launches Synveil nor enables startup.
Exact distribution qualification remains assigned to P018 and P020.

## Consequences

The package carries a visible desktop entry and icon, exact runtime dependency
metadata, noninteractive hooks, and a user service definition that stays
disabled. CI artifact/package-manager evidence is not a graphical clean-machine
claim. RPM UX, AppImage, quick install, and first-launch integration are deferred.

## Alternatives

A custom Synveil package wizard was rejected because it would duplicate native
authorization and transaction ownership. Bundling development SDKs was rejected
in favor of native runtime dependency resolution.

## Migration and review trigger

Review if native package-handler requirements, the executable path, or the
qualified architecture changes.

The native-package workflow retains strict package reproducibility checks.
Hosted Prompt013 evidence proves DEB byte reproducibility but currently exposes
an RPM-only byte-reproducibility defect. That RPM gate remains strict and
P014-owned; it is sequenced after Prompt013's scoped DEB and retained packaging
evidence rather than converted into a warning.
