# ADR-070: v0.2 library first-run wizard

Status: Accepted — Prompt040
Date: 2026-10-06
Owners: Synveil desktop and client maintainers

## Context

The desktop already has a canonical `SetupLibrary { name, root_path }`
operation, a native folder picker, safe first-bind validation, pending setup
recovery, authoritative response-loss reconciliation, and durable runtime
activation. Prompt040 closes the product gap: the authenticated zero-library
state currently presents that operation as a technical card inside the normal
dashboard.

## Decision

### Routing derives from authoritative state

The first-library page is shown only for a fresh snapshot with a configured
profile, an authenticated device, and no configured local libraries. P037
Welcome, P038 connection setup, and P039 sign-in keep precedence. Existing
libraries bypass the page. QML stores no first-run-complete flag. A new
controller after GUI restart reconstructs the destination from client-owned
state.

### Presentation requests the existing client operation

The one-page surface asks only for a library name and a directory selected by
the native Qt folder picker. `DesktopUiBridge` dispatches to the existing
`DesktopController` and local client control path. No second server client,
library registry, sync engine, persistence owner, filesystem watcher, or
credential owner is introduced. The chosen local path is not sent in remote
library metadata.

### Existing-folder and pending-setup safety follow ADR-045

A safe non-empty folder is valid for creation of a new remote library.
Ordinary local entries remain in place and enter the existing bounded
observation and synchronization pipeline. The initial remote root does not
authorize deletion of local entries. Existing path, overlap, `.synveil`
control-tree, identity, profile, and platform checks remain client-owned. No
arbitrary existing-remote-library attach/import flow is added.

An interrupted setup reuses its durable pending identity and asks the user to
select the same folder again when needed. An uncertain response requests an
authoritative state refresh and never blindly repeats the remote create. The
wizard remains until a newer fresh snapshot confirms a configured library; a
command result by itself is not UI success.

### Later phase handoffs

After the configured library is visible, the normal product surface takes
over. P040 does not wait for or claim first synchronization. P041 owns
installation-to-sync progress; P042 owns broader repair and recovery UX. The
Phase-F readiness checkpoint remains reserved for completion of P042.

## Consequences

- First setup is a focused product page rather than a dashboard card.
- Fresh client state remains the sole routing authority.
- Existing folder admission, pending identity, reconciliation, durable-first
  binding, and runtime ownership remain unchanged.
- Users can safely start from ordinary existing files without a mass-delete
  interpretation.
- No schema migration, new server API, or change to authentication is needed.

## Alternatives rejected

- A QML completion flag would diverge after sign-out or restart.
- Hiding the wizard on a successful command result could display false success
  before library state refreshes.
- A QML-owned validation or HTTP path would duplicate the client authority.
- Treating the empty new remote root as a request to delete local entries
  would violate ADR-045.
- Matching or adopting an existing remote library by name would invent an
  unsupported attach/import contract.

## Review trigger

Revisit if the authoritative library snapshot or canonical setup operation
changes, if an existing-remote attach/import contract is introduced, or if
root-safety ownership moves from the client.
