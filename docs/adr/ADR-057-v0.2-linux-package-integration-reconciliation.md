# ADR-057: v0.2 Linux package integration reconciliation

- Status: Accepted — Prompt012 contract
- Date: 2026-09-29

## Context

Synveil already produces DEB and RPM packages while Phase B introduced one
common lifecycle, journal, preservation, and error model. Native package state
and predominantly user-scoped Synveil state have different authorities.

## Decision

dpkg/APT and RPM/DNF remain authoritative for package transactions,
dependencies, locks, and their databases. The common engine coordinates typed
product lifecycle semantics without generic shell execution. Linux platform
integration owns only the declared Synveil integration surfaces; it never owns
arbitrary user or server durable data. Ordinary upgrade, repair, uninstall,
DEB purge, and RPM erase preserve durable Synveil state. Installing static unit
files does not authorize enabling or starting them.

All files physically shipped and tracked by DEB/RPM—including desktop,
systemd, icon, sysusers, and tmpfiles metadata—are `PACKAGE_OWNED` filesystem
payload under native-manager authority. Semantic platform integration remains a
distinct authority only for effects outside package payload. Schema 1 uses
closed, ordered format-specific architectures, dependencies, and hooks, and
preserves the complete P009 set including `APPLICATION_CONFIG`. Live-path
inspection rejects unsafe lexical paths, symlink ancestry, and an unsafe root.

## Consequences

Both formats share one schema-1 reconciliation contract and fail closed on
unknown ownership, incompatible upgrades, missing verification, or unknown
outcomes. Package hooks cannot infer an end user from a privileged environment.
P008 records Synveil integration mutations but does not replace native package
journals. Native clean-machine qualification and polished distro UX remain
deferred through P020.


The v1 reconciliation contract also fails closed on product identity and package-payload surface drift: every PACKAGE/TEMPLATE MANIFEST entry must appear exactly once in the Prompt012 package surface contract, and the contract may not invent additional package-owned paths.
