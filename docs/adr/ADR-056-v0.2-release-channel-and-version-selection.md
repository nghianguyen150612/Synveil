# ADR-056: v0.2 release channel and version selection

- Status: Accepted — Prompt011 contract
- Date: 2026-09-29

## Context

P005 identifies releases and P006 authenticates exact manifests and artifacts,
but neither determines which stable release a supported installation should
use. A mutable remote recommendation requires authenticity and rollback
protection independent of TLS and product-version ordering.

## Decision

Version 1 has only `stable` and exact numeric `MAJOR.MINOR.PATCH` releases.
Authenticate bounded exact channel bytes from local pins or locally trusted
signature schemes/key IDs, with no TOFU. A positive generation, trusted minimum,
and caller-owned generation/digest high-water reject rollback and equivocation.
Compatibility is a sorted finite list of exact older `upgrade_from` versions.
Choose the highest fresh-install eligible release or highest newer compatible
upgrade and never downgrade.

The selected object remains structurally attached to its authenticated channel
and pins exact P005 manifest size, digest, version, and source commit for P006.
P006 remains manifest/artifact authority; P009 remains mutation authority.
Selection does not imply platform artifact availability and does not implement
an automatic updater.

## Consequences

Metadata is deterministic, reviewable, clock-independent, and safely replayable
at the same generation/digest. Channel expansion, production signing/key
provisioning, platform qualification, automatic updates, and release creation
remain deferred.


## Review hardening

The accepted design requires high-water evaluation to be part of every selection call rather than an optional adjacent helper. Authentication evidence must match the supplied local pin or locally trusted detached-signature key/scheme. Selected-release objects are not trusted merely because their release dictionary appears in the authenticated channel: selection mode and current-version eligibility are revalidated before manifest handoff.
