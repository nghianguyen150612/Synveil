# ADR-073: v0.2 installer security hardening

- Status: **Accepted — P043 source decision; release provisioning remains separate**
- Date: 2026-10-07
- Decision owners: Release, Security, Platform / Distribution

## Context

ADR-051 already reserves an approved verifier behind P006, locally established
trust roots, stable identities and overlap rotation. Current main implements
only injected signature callbacks. P009 trusts a compatibility disposition
without independently checking version order. Platform implementations also
need stricter ownership and ancestry checks without changing installer owners.

## Decision

Use Ed25519 as the single production detached-signature scheme, through the
maintained `cryptography` library and its OpenSSL backend. The reviewed Python
dependency is pinned in `scripts/requirements-installer-security.txt`. Verify
exact raw metadata bytes with 32-byte public keys and 64-byte signatures;
unavailable, unknown and malformed verification fails closed with no fallback.
Keep the existing independent pinned-digest bootstrap mode.

Only an explicit local public policy can establish production trust. Its
schema and purpose are exact, and IDs are `synveil-release-` followed by SHA-256
of the raw public key. Neither CI, filenames nor metadata install roots. No
project production public root or private material is created by P043. Release
operators must provision and independently distribute a deliberate public root
before production signature distribution. Rotate through locally deployed
old/new overlap, then remove the retired key; descriptors never authorize keys.

Persist P017's caller-owned P011 high-water under its private installer state
root. An exclusive owned lock protects compare/update; P011's existing
`evaluate_high_water` remains the sole rollback/equivocation authority. Unknown
schemas remain untouched. This is channel freshness evidence, not a competing
installation transaction journal or a replacement for P008 reconciliation.

Independently require strict stable increasing versions in P009 Upgrade;
exact equality belongs to Repair. Windows Setup embeds explicit release-owned
upgrade sources, rather than assuming every newer version is compatible. The
current production policy has no approved older sources. Native pre-unpack
hooks likewise reject unknown/different versions; future upgrade support needs
explicit policy, not a force flag. These conservative gates do not certify an
upgrade path or implement P044.

AppImage ownership records advance to schema 2 to bind the producing helper's
product version. Unreadable, older/missing or future records cannot authorize
repair/removal or be silently reset. Explicit future migrations belong to the
existing lifecycle owner. User-level integration is not release authentication.

## Consequences

The existing P005/P006/P007/P008/P009/P011 and native-package authorities remain
singular. Windows remains per-user, AppImage remains user-level, and Linux
only elevates the exact native package operation after consent and verification.
Trust, path or schema failures stop; no recovery reset or weaker mode is added.

A compromised signing key or a principal controlling the installer's own code,
local trust policy and user identity is outside publisher-authentication's
protection. Private staging and last-use checks protect against remote bytes,
other users and accidental replacement; they do not claim immunity from the
same principal replacing its own code/policy. Native clean-machine acceptance,
production key custody/URLs, resilience and final release gates remain later work.

## Alternatives

Reject checksum-only trust, TOFU, keys fetched beside signatures, environment
trust switches, custom cryptography, shell package templates, machine-wide
Windows installation, and unrestricted destructive repair.

## Review trigger

Review production root provisioning/rotation, any additional signature scheme,
new compatibility sources, ownership-record migrations, or a privilege/owner
change. Preserve authenticate-before-use, exact artifact identity, scoped
native authority and reconcile-before-retry.
