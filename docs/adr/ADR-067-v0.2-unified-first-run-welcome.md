# ADR-067: v0.2 unified first-run Welcome

Status: **Accepted**

Date: 2026-10-04

Decision owners: Desktop, Product, Security, Accessibility

## Context

An opaque client profile identity can exist before it has a server origin, and
P036 separately derives managed Host state. Neither a page index nor a global
“welcome completed” flag proves that either setup succeeded.

## Decision

Fresh first run offers exactly two equivalent primary intents: **Host Synveil**
and **Connect to Synveil**. Merely displaying Welcome performs no mutation.
Host activation alone delegates explicit intent to the P036 coordinator;
Connect enters the existing client/profile controller path and never invokes a
Host owner. Startup derives its destination from canonical client configuration
and P036 inspection. Partial Host state resumes, Ready is not reprovisioned,
and a configured profile bypasses Welcome even after sign-out.

The startup-preference prompt is sequenced after client onboarding begins.
P038 owns connection simplification, P039 authentication polish, P040 local
client-library selection, P041 cross-stage progress, and P042 repair UX.

## Consequences

QML owns only ephemeral routing presentation. It cannot persist completion or
reconstruct the Host state machine. Unsupported Host remains explained while
Connect remains usable. Server data and the future client sync folder remain
distinct concepts.

## Alternatives

A persisted completion flag, automatic default choice, GUI networking, and
Linux-only QML capability checks were rejected because each duplicates or
bypasses a canonical owner.

## Migration and review trigger

Retarget this stacked change to main only after P036 merges. Review if final
P036 inspection/admission APIs change or a durable reset owner is introduced.
