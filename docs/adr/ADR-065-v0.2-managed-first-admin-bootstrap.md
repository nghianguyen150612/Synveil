# ADR-065: v0.2 managed first-admin bootstrap

Status: **Accepted**
Date: 2026-10-04
Decision owners: Auth / Security, Server Setup, Operations

## Context

Synveil already has a PostgreSQL-authoritative, atomic first-administrator
implementation. A managed LAN edge must not let an unauthenticated peer race
the person at the host, while operator-managed deployments need compatibility.

## Decision

PostgreSQL `bootstrap_state` remains the sole authority. The existing
`AuthenticationService` and `AuthRepository` transaction, including its
singleton `FOR UPDATE` lock, Argon2id verifier and initial Library/root, remain
the only creation path and permit exactly one first administrator.

Managed Personal/Home creation is machine-local through the loopback backend.
Every Synveil-owned HTTPS edge blocks the mutation before proxying and does not
use spoofable forwarding headers. No setup-secret query, URL, or request-body
workaround is introduced. Advanced external proxy exposure remains explicitly
operator-owned.

Closure is permanent through ordinary restart, repair, reinstall and network
or storage lifecycle operations. Creation issues no session; explicit normal
login follows and must prove instance-admin authority. Inconsistent state
fails closed and requires operator repair rather than destructive auto-reset.

## Consequences

P036 receives typed inspection, canonical creation and explicit-login
verification boundaries. Lost responses are reconciled against PostgreSQL and
never cause an automatic second administrator. Managed remote abuse surface is
removed without inventing another durable secret.

## Alternatives

Remote setup tokens, forwarding-header locality, a second management listener,
and filesystem/config closure flags were rejected as weaker or duplicate
authorities. Removing the legacy endpoint was rejected because it would
unnecessarily break explicitly secured operator deployments.

## Migration and review trigger

Review only if the authoritative database model or managed edge ownership
changes. Any remote managed claim flow requires a separate threat model and
accepted ADR; ordinary lifecycle work must never reopen bootstrap.
