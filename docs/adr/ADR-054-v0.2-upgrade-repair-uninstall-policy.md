# ADR-054: v0.2 upgrade, repair, uninstall policy

- **Status:** Accepted — Prompt009 contract
- **Date:** 2026-09-29

## Decision

Use the existing `synveil-install-engine` as the single shared lifecycle-policy authority. Exact, explicit compatibility and verified artifacts gate Upgrade. Repair is same-version package/integration restoration only. Ordinary Uninstall removes proven installation-owned state and always preserves durable product/user/server state. Explicit startup choices are preserved.

Purge is a separate typed destructive contract with exact authorized scope, target identity, canonical ownership, containment, and symlink checks. Generic installer purge represents only application configuration; credential removal remains OS SecretStore-owned and client-state removal remains synveil-client-owned. Generic library, server-data, native-package-database, and external-dependency purge is forbidden. The installer does not own application or database migration and does not promise unsafe binary rollback.

All mutable lifecycle work remains a P007 plan and must use the P008 journal. Lifecycle operations are accepted only when their operation, owner, resource class, and authority match the canonical mapping. Matching native-package, integration, and runtime state must be authoritatively known before mutation, and credential-preservation evidence must have a coherent non-secret presence/identity pair. Active or ambiguous transactions reconcile first; no blind replay is introduced.

## Consequences

Platform adapters receive deterministic constraints but retain native authority. Unknown ownership and preservation evidence fail closed. P010 maps finite results to messages and P011 selects a concrete target release.
