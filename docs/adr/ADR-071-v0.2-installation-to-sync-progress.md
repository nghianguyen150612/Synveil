# ADR-071: v0.2 installation-to-sync progress projection

Status: Accepted — Prompt041
Date: 2026-10-06
Owners: Synveil desktop, client, and client-sync maintainers

## Context

P037–P040 already own Welcome, connection setup, authentication, and
authoritative library creation. The desktop needed one understandable journey
through those results and the first bounded synchronization without observing
native installer milestones or duplicating any owner state machine.

## Decision

The desktop exposes one Rust-owned five-stage product projection:

```text
Synveil ready → Server ready → Signed in → Library ready → First sync
```

Stages have finite semantic states: pending, active, waiting, complete, and
action required. QML renders typed stage values and bounded product copy.
Installation is represented only as **Synveil ready**, because the desktop has
no reliable cross-platform native-installer completion signal.

First synchronization completion is durable local evidence set only by the
existing client-sync runtime after a true `SyncCycleResult::is_idle()` result
with no pending follow-up wake. The safe controller snapshot must also show a
fresh current generation, available root, ready authentication, no unresolved
conflict, and a non-running/non-scheduled runtime. Progress, requested work,
partial durable progress, and `more_work_likely()` never complete the stage.

Existing replicas default to completed evidence during migration; new library
bindings start unproven. This preserves normal routing for existing users and
reconstructs the experience after GUI restart without a QML completion flag.

Waiting covers bounded retry/reconciliation states. Action required routes
only to already-supported sign-in, resume, conflict, or safe status actions.
Broad repair and recovery remain P042.

## Consequences

- Users see meaningful stage-level progress without fake percentages.
- Native installer and package-manager ownership is unchanged.
- The sync supervisor and fairness scheduling are unchanged; the evidence hook
  is observational and bounded.
- Snapshot generation, revision, freshness, root, auth, and conflict fences
  remain authoritative.
- The projection exposes no credentials, roots, file data, hashes, database
  rows, or internal engine terminology.

## Alternatives rejected

- A second installer/setup/sync state machine would create competing truth.
- A QML timer or percentage would fabricate progress.
- Treating library creation or a `Progress` result as first-sync completion
  would misrepresent bounded multi-cycle synchronization.
- A persisted GUI-only completion flag would become stale after restart or
  newer sync work.
- A general repair console would cross the P042 boundary.

## Review trigger

Revisit if native installer completion becomes a reliable desktop input, if
the sync runtime changes its quiescence contract, or if P042 introduces
supported repair actions that can be safely composed into this projection.
