# ADR-063: v0.2 managed server services

- Status: **Accepted**
- Date: 2026-10-04
- Owners: Server, Platform, Security, Distribution

## Context

Personal/Home hosting needs a machine-level runtime which survives logout while
keeping replaceable software separate from durable PostgreSQL and object data.
The desktop package cannot own hosted-server removal.

## Decision

Ubuntu 24.04 and Fedora 42 x86_64 use systemd system services and boot-enabled
`synveil-server.target`. API/worker/migration use `synveil`; private PostgreSQL
17 uses distinct `synveil-postgres`. A distinct closed SERVER_PACKAGE and a
separate verified PostgreSQL runtime select immutable versioned roots via
root-owned atomic pointers. One UUIDv7 marker binds the durable cluster to the
server and real PostgreSQL system identifier. Ordering is PostgreSQL, canonical
MigrationRunner gate, API, worker; shutdown reverses it. Secrets use
`LoadCredential=`. PostgreSQL and API remain loopback-only. Repair and software
removal preserve config, secrets, database/cluster, and object data.

AdvancedExternal installs only Synveil application services and never manages
the operator database. P034 owns exposure; P035 owns initial admin; P036 owns
the guided end-to-end acceptance.

## Consequences

Hosted services survive desktop logout/uninstall and have least-privilege,
separate data authority. Installation needs a short-lived bounded privileged
coordinator and strict identity inspection. Major PostgreSQL upgrades and
destructive purge remain unsupported.

## Alternatives

User services, desktop-package ownership, PostgreSQL as root/`synveil`, public
database listeners, environment secrets, blind initdb, and destructive repair
are rejected.

## Review trigger

Revisit for another supervisor/platform, PostgreSQL 18 migration, encrypted
systemd credentials, or an exact-scope destructive purge authority.
