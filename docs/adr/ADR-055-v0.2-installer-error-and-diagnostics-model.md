# ADR-055: v0.2 installer error and diagnostics model

- **Status:** Accepted — Prompt010 contract
- **Date:** 2026-09-29

## Context

P006-P009 intentionally expose precise internal acquisition, engine, journal/recovery, and lifecycle failures. Later installers need simple user-facing errors without weakening those safety boundaries or leaking implementation details.

## Decision

Use one finite platform-neutral presentation model in `synveil-install-engine`.

Error category and retry permission are separate contracts. `OutcomeUnknown`, unresolved recovery, failed compensation, and ambiguous journal state require reconciliation and never map to blind replay. Trust/integrity failures require fresh evidence and never expose a verification bypass. Protected ownership, preservation, and purge failures never expose a destructive workaround.

Map every existing P006/P007/P008/P009 source code explicitly. P006's Python acquisition codes are pinned by a machine-readable fixture and AST drift validator; Rust uses a closed matching enum. Unknown acquisition strings fail closed without being echoed.

Diagnostics are typed rather than free-form. Serialized Details are limited to 4096 bytes; safe IDs are limited to 96 bytes; source codes to 64 bytes; secondary actions to two. Paths, URLs, commands, exception text, stdout/stderr, environment dumps, secrets, authentication material, connection strings, private keys, and legacy free-form evidence do not cross this boundary.

Stable `installer.error.*` message keys and finite actions describe semantics. English/Vietnamese reference copy must preserve the same condition, risk, and safe next action. Later UI code owns layout and localization infrastructure.

No telemetry or automatic diagnostic upload is introduced.

## Consequences

New internal failure variants must receive an explicit mapping before compilation/tests can remain complete. Later platform adapters may contribute only typed preflight/platform facts. User interfaces can render safe recovery choices without understanding journal or engine internals.

P011 still owns release channels and compatible version selection; Prompt010 may recommend choosing a supported version but never decides which release is latest, stable, recommended, or beta.
