# ADR-061: v0.2 managed server configuration and secret ownership

## Status / Trạng thái

**Accepted / Chấp thuận — Prompt031**

## Date / Ngày

2026-10-03

## Context (English)

ADR-059 defines the ordinary Host setup boundary. ADR-060 selects a private
Synveil-managed PostgreSQL 17 runtime for Personal/Home and explicitly
operator-managed PostgreSQL 17 for Advanced. The existing API still has
operator-oriented environment inputs, while scheduled maintenance already
uses ADR-025's protected `LoadCredential=` delivery. Later Host work needs a
single durable authority and stable secret ownership without provisioning the
database or exposing listeners in this decision.

## Decision (English)

1. A managed Host has one canonical, versioned, non-secret JSON authority at
   `/etc/synveil/server-config.json`. Schema V1 is bounded to 32 KiB, uses
   strict typed objects that deny unknown fields, and rejects unknown future
   versions without rewriting them.
2. The authority contains one stable local installation UUIDv7, explicit
   deployment profile, PostgreSQL major 17 and ownership, non-secret resolved
   endpoint metadata, fixed credential references, dependency/data-root
   identity, pending storage and network states, service topology version,
   configuration state, and an explicit generation. It contains no secret
   material. Its canonical-byte fingerprint is diagnostic/CAS input only, not
   authentication.
3. V1 has only `PersonalHomeManaged` (private Synveil-owned PostgreSQL 17) and
   `AdvancedExternal` (operator-owned external PostgreSQL 17). No SQLite,
   Docker Personal/Home, system PostgreSQL auto-adoption, or other PostgreSQL
   major is introduced.
4. Secret values live in a separate protected source directory. Linux Gen-1
   paths and modes are `/etc/synveil` `root:synveil 0750`, config
   `root:synveil 0640`, `/etc/synveil/credentials` `root:root 0700`, and
   individual credential sources `root:root 0600`. Stable identifiers include
   `database-url`, `database-password`, and `rebaseline-token-key`. Values are
   never serialized, logged, or included in ordinary diagnostics.
5. Fresh managed setup generates a 32-byte database role password and a
   32-byte rebaseline key, each represented as 64 lowercase hexadecimal
   characters in its own protected source file. External PostgreSQL input is
   validated as a bounded PostgreSQL URL and stored only as the protected
   `database-url` credential. Existing valid identity and secrets are
   preserved. Missing, malformed, partial, future, or ambiguous state fails
   closed; repair does not rotate, replace, or delete secrets or data.
6. Durable secret creation is exclusive, restrictive before data exposure,
   synced and verified. Config changes use a same-directory exclusive
   temporary, file sync, atomic replacement, parent sync, read-after-write
   verification, and a generation/fingerprint compare-and-swap. Unknown write
   outcomes are reconciled by inspecting the final target.
7. Runtime services read configuration read-only. API and worker share the
   existing bounded database credential loader; systemd `LoadCredential=` is
   the production delivery mechanism, preserving ADR-025. A protected file and
   plaintext `DATABASE_URL` or rebaseline-key environment input together are
   ambiguous and rejected. Legacy explicit operator/developer environment
   configuration remains supported when managed configuration and credential
   files are not selected.
8. Platform paths belong to the server configuration adapter, not domain core.
   Storage, services/PostgreSQL initialization, reachability, first-admin
   bootstrap, and end-to-end acceptance remain P032, P033, P034, P035, and P036
   respectively. This ADR grants none of those authorities.

## Consequences (English)

Later Host steps can update typed configuration fields without constructing an
environment dictionary, handling secrets in UI, or competing over multiple
files. Operators retain a deliberate legacy mode, with fail-closed behavior
when authorities conflict. The source-secret files are not directly readable
by the runtime identity; the later service installer must provide per-service
credential copies using ADR-025. Fixture permission tests do not qualify
physical `/etc` ownership or a complete Host installation.

ADR-025 is extended, not superseded: `LoadCredential=` and its least-privilege
properties remain locked. ADR-059 and ADR-060 remain authoritative for product
and database strategy. No P028 Windows acceptance, guided Host readiness, or
public reachability is asserted.

## Bối cảnh (Tiếng Việt)

ADR-059 xác định ranh giới thiết lập Host thông thường. ADR-060 chọn runtime
PostgreSQL 17 riêng tư do Synveil quản lý cho Personal/Home và PostgreSQL 17
bên ngoài do operator quản lý rõ ràng cho Advanced. API hiện vẫn có biến môi
trường thiên về operator; scheduled maintenance đã dùng cơ chế phân phối
`LoadCredential=` được bảo vệ theo ADR-025. Các bước Host sau cần một authority
bền vững duy nhất và ownership secret ổn định, nhưng quyết định này không cấp
quyền provision database hoặc mở listener.

## Quyết định (Tiếng Việt)

1. Managed Host có một authority JSON không chứa secret, có version, tại
   `/etc/synveil/server-config.json`. Schema V1 giới hạn 32 KiB, dùng kiểu
   strict từ chối field lạ, và từ chối version tương lai mà không ghi đè.
2. Authority chứa UUIDv7 ổn định cục bộ, profile rõ ràng, PostgreSQL major 17
   và ownership, endpoint không bí mật khi đã phân giải, tham chiếu credential
   cố định, identity dependency/data-root, trạng thái storage/network chờ,
   version topology service, trạng thái cấu hình và generation tường minh.
   Không chứa secret. Fingerprint của byte canonical chỉ phục vụ chẩn đoán/CAS,
   không phải xác thực.
3. V1 chỉ có `PersonalHomeManaged` (PostgreSQL 17 riêng tư do Synveil sở hữu)
   và `AdvancedExternal` (PostgreSQL 17 bên ngoài do operator sở hữu). Không
   bổ sung SQLite, Docker Personal/Home, tự động nhận PostgreSQL hệ thống hay
   major khác.
4. Giá trị secret nằm trong thư mục nguồn được bảo vệ riêng. Linux Gen-1 dùng
   `/etc/synveil` `root:synveil 0750`, config `root:synveil 0640`,
   `/etc/synveil/credentials` `root:root 0700`, và file nguồn `root:root 0600`.
   ID ổn định gồm `database-url`, `database-password`,
   `rebaseline-token-key`. Không serialize, ghi log hoặc đưa giá trị vào chẩn
   đoán thông thường.
5. Setup managed mới tạo mật khẩu database 32 byte và rebaseline key 32 byte,
   mỗi giá trị biểu diễn bằng 64 ký tự hex thường trong file nguồn riêng. URL
   PostgreSQL external được kiểm tra có giới hạn và chỉ lưu thành credential
   `database-url` được bảo vệ. Identity/secret hợp lệ được giữ nguyên. State
   thiếu, sai, dở dang, tương lai hoặc mơ hồ fail closed; repair không rotate,
   thay thế hay xóa secret hoặc dữ liệu.
6. Tạo secret bền vững dùng exclusive create, quyền hạn chế trước khi lộ dữ
   liệu, fsync và xác minh. Thay đổi config dùng temporary độc quyền cùng thư
   mục, fsync file, thay thế nguyên tử, fsync parent, đọc xác minh và CAS bằng
   generation/fingerprint. Kết quả ghi không rõ phải được đối soát bằng cách
   inspect target cuối.
7. Runtime đọc config read-only. API và worker dùng chung bounded database
   credential loader hiện có; `LoadCredential=` là cơ chế production, giữ
   nguyên ADR-025. File được bảo vệ đồng thời với `DATABASE_URL` hoặc key env
   dạng plaintext là mơ hồ và bị từ chối. Legacy env rõ ràng của operator/dev
   vẫn được hỗ trợ khi managed config và file credential không được chọn.
8. Path platform thuộc adapter server config, không thuộc domain core. Storage,
   service/khởi tạo PostgreSQL, reachability, bootstrap admin đầu tiên và
   acceptance end-to-end lần lượt thuộc P032–P036. ADR này không cấp các quyền
   đó.

## Hệ quả (Tiếng Việt)

Các bước Host sau có thể cập nhật field config typed mà không tạo dictionary
môi trường, xử lý secret trong UI hay cạnh tranh nhiều file. Operator vẫn có
legacy mode rõ ràng; các authority xung đột bị từ chối. Runtime identity không
đọc trực tiếp file secret nguồn; trình cài service tương lai phải phân phối
bản credential riêng theo ADR-025. Test quyền trong fixture không chứng minh
ownership `/etc` vật lý hay một Host hoàn chỉnh.

ADR-025 được mở rộng, không bị thay thế: `LoadCredential=` và thuộc tính least
privilege vẫn khóa. ADR-059/060 tiếp tục có thẩm quyền về sản phẩm và database.
Không khẳng định P028 Windows acceptance, readiness Host có hướng dẫn hoặc
reachability công khai.
