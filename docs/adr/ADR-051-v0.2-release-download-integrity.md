# ADR-051: v0.2 release acquisition and integrity trust boundary

Status: **Accepted**

Date: 2026-09-28

Decision owners: Synveil release and installation maintainers

## Context

An artifact checksum in metadata from the same unauthenticated source proves
byte consistency, not publisher identity. Prompt006 needs a reusable acquisition
primitive without assuming P011 channel policy or performing installer effects.

## Decision

Authenticate exact, bounded P005 manifest bytes before parsing or using their
semantics. Local `ReleaseTrustPolicy` supplies trusted pins, origins, limits,
schemes, and key IDs; remote data cannot establish trust and TOFU is forbidden.
Pinned SHA-256 authentication is implemented. A versioned detached-signature
descriptor and injected verifier boundary are defined, but fail closed until an
approved backend and locally trusted production key are configured.

Require HTTPS and normal certificate validation. Reject credentials in URLs.
Evaluate no more than five redirects and reject downgrades, loops, or targets
outside the explicit allowlist. Combine only a trusted base URL with P005's safe
filename.

After P005 validation, select exactly one artifact by exact version, platform,
normalized architecture, artifact type, and role. Stream into a secure file in
the destination root, enforce manifest size as a hard bound, hash while writing,
fsync, and atomically promote only verified bytes. Existing files are reverified
or rejected; partial bytes never reach the final name.

Key IDs are stable and locally configured. Rotation uses overlap: trust the new
key before new-only signatures, and stop accepting revoked keys for new release
metadata. Unknown keys and algorithms fail closed. Private production keys are
never source-controlled or logged; test keys cannot enter production policy.

P011 retains channel/latest/version-ordering ownership. P017 owns quick-install
UX. P007 and later prompts own installer execution; acquisition never executes
the staged artifact.

## Consequences

Callers must possess a trusted manifest pin until production signature
provisioning is complete. Release evidence can identify the exact authenticated
manifest and artifact. Downloads cannot silently cross origin, version,
architecture, or destination boundaries.

## Alternatives

Trusting HTTPS alone, trusting a checksum beside the artifact, TOFU, downloading
a key beside its signature, permissive redirects, and verify-after-install were
rejected because they do not establish the required publisher and byte chain.

## Migration and review trigger

Review when an approved signature backend and production key are provisioned,
or when P011 defines channel endpoints. Preserve the authenticate-before-parse
and verify-before-promote invariants.
