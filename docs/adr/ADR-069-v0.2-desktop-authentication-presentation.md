# ADR-069: v0.2 desktop authentication presentation

**Status:** Accepted

**Date:** 2026-10-05

**Decision owners:** Synveil maintainers

## Context

ADR-042 secures desktop device enrollment, but its implementation terminology
and one-click sign-out exposed unnecessary complexity in the ordinary UI.

## Decision

Authentication remains the one-time device-enrollment protocol. Product UI
calls its transient input a **one-time device code**. QML owns only masked,
sensitive, bounded collection and presentation; the client process remains the
HTTP and `SecretStore` owner. Controller and process admission permit one
authoritative authentication operation, and QML clears its field immediately
after an admitted dispatch.

Durable credential promotion and verification precede success UI.
`OutcomeUnknown` causes canonical reconciliation and never automatic enrollment
replay. Sign out is explicit, confirmed, and reported successful only after its
durable lifecycle completes. It preserves server profile configuration,
libraries, and origin fencing. P040 owns first-library onboarding.

## Consequences

The UI shows bounded typed states and safe errors without server verification
detail. Restarts recover status from client-owned durable state. Users must
obtain a fresh code when an unauthenticated unknown outcome cannot be confirmed.

## Alternatives

Password login, browser auth, QR pairing, QML credential ownership, automatic
replay, and profile reset on sign-out are rejected because they change the
protocol or weaken its security boundary.

## Migration and review trigger

Revisit only when the canonical desktop authentication protocol or credential
owner changes. Presentation wording alone does not require protocol migration.
