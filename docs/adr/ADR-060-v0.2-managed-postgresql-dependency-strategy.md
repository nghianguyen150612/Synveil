# ADR-060: v0.2 managed PostgreSQL dependency strategy / Chiến lược dependency PostgreSQL managed v0.2

## Status / Trạng thái

**Accepted / Chấp thuận — Prompt030 strategy contract**

## Date / Ngày

2026-10-03

## Decision owners / Chủ sở hữu quyết định

Database, Release, Security, Product, and Platform / Cơ sở dữ liệu, phát hành,
bảo mật, sản phẩm và nền tảng

## Context (English)

ADR-002 makes PostgreSQL the canonical server authority and ADR-059 requires a
guided Personal/Home Host path without database administration. Repository live
integration targets PostgreSQL 17, while current operation still requires an
operator-supplied database. ADR-019 intentionally left private, system-managed,
separately packaged, and external-only distribution unresolved. The choice must
now be closed without creating SQLite production semantics or treating design
as runtime evidence.

## Decision (English)

1. Personal / Home v0.2 uses a **Synveil-managed private PostgreSQL 17
   runtime**, acquired as a distinct authenticated server dependency only after
   explicit Host intent. Desktop installation and Connect do not acquire it.
2. The runtime is isolated, private/local, deterministic, unshared, not a
   global OS PostgreSQL service, and requires neither pre-existing PostgreSQL
   nor Docker/Compose. An unrelated detected cluster is external infrastructure
   and is never silently adopted.
3. Advanced / Server Mode retains explicit external operator-managed
   PostgreSQL. v0.2 qualification requires PG17 in both profiles. Both use the
   same schema, ordered forward migrations, and application logic.
4. `POSTGRESQL_RUNTIME` is a `SERVER_PACKAGE`, distinct from
   `SERVER_DATABASE`, configuration, secrets, and object data. Runtime repair,
   update, or removal never authorizes cluster deletion. Ordinary desktop
   uninstall does nothing to it; explicit server-software removal preserves all
   durable server state by default.
5. Dependency identity binds upstream version/major, component, platform,
   architecture, packaging version, digest, provenance, license/notices,
   inventory, compatibility, and release/channel. Acquisition reuses P005,
   P006, and P011 trust rules; unsigned, mutable, unpinned, or integrity-bypassed
   acquisition is forbidden. Exact verified offline inputs remain possible.
6. Synveil owns managed runtime security/maintenance delivery. Verified
   same-major replacement requires preflight, controlled lifecycle, and health
   verification without recreating state. A future major requires a separately
   validated database-upgrade path; no automatic major upgrade or arbitrary
   database rollback is promised in v0.2.
7. Initialization authority exists only after preflight, Host consent,
   dependency verification, and target-ownership validation. Unknown,
   unsupported, partial, foreign, or outcome-unknown state is inspected and
   fails closed; no blind `initdb`, reset, role recreation, or drop/create.
8. A dedicated restricted process identity and private cluster directory are
   required. Normal UI exposes only “System database,” never credentials,
   `DATABASE_URL`, ports, or database internals. P031 and P033 select exact
   secret, path, permission, endpoint, and service mechanisms.
9. Ubuntu 24.04 and Fedora 42 x86_64 are managed-Host **implementation
   targets**, not shipped support. Windows, macOS, and other Linux
   architectures are **NOT_YET_QUALIFIED** for managed Personal/Home Host.
   Windows/Linux client support and Advanced deployments are unaffected.
10. Backup/restore capability and coordinated database/object recovery are
    acceptance requirements. P036 must prove the Host path and measure the
    non-zero runtime footprint before support is claimed.

The complete normative lifecycle, matrix, threat review, failure language, and
P031–P036 handoffs are in
[SERVER_DEPENDENCY_STRATEGY.md](../v0.2/SERVER_DEPENDENCY_STRATEGY.md).
This ADR supersedes the unresolved distribution portion of ADR-019 and closes
OD-PLAT-001.

## Consequences (English)

Ordinary users receive deterministic database compatibility and ownership
without administering PostgreSQL. Synveil assumes substantial packaging,
provenance, security-update, service, repair, compatibility, and support cost;
the OS does not automatically patch the private runtime. Host-time download and
runtime resource costs are real, while Connect remains unaffected. Platform
support is narrower until adapters and acceptance exist. Compose remains an
Advanced topology. No provisioning implementation or readiness is claimed.

## Alternatives (English)

- **System-global PostgreSQL:** rejected for Personal/Home because distribution
  drift, shared settings/ports, credentials, ownership, upgrades, and uninstall
  are ambiguous.
- **Docker/Compose requirement:** rejected for normal mode because it adds a
  privileged runtime, networking, image, and volume lifecycle ordinary users
  did not choose; retained for Advanced operators.
- **External-only PostgreSQL:** rejected for normal mode because it transfers
  administration rather than automating it; retained explicitly in Advanced.
- **SQLite or another authority:** rejected because it splits schemas,
  migrations, transactional behavior, and correctness.

## Migration and review trigger (English)

P031–P036 implement and qualify this contract. Changing the managed major,
adopting a system/global or container prerequisite, combining runtime with
durable data, broadening platform support, changing external ownership, or
adding a second database authority requires compatibility evidence and a
superseding ADR. A qualified PG17 patch artifact does not by itself reopen this
decision; a PostgreSQL major upgrade does.

## Bối cảnh (Tiếng Việt)

ADR-002 chọn PostgreSQL làm authority chuẩn tắc của server và ADR-059 yêu cầu
luồng Host Personal/Home có hướng dẫn mà không bắt user quản trị database. Test
integration live hiện nhắm PostgreSQL 17, còn vận hành hiện tại vẫn cần database
do operator cung cấp. ADR-019 cố ý để ngỏ lựa chọn private, system-managed,
package riêng hay external-only. P030 phải đóng lựa chọn mà không tạo semantics
production SQLite hoặc coi thiết kế là bằng chứng runtime.

## Quyết định (Tiếng Việt)

1. Personal / Home v0.2 dùng **runtime PostgreSQL 17 private do Synveil quản
   lý**, được lấy như dependency server riêng có xác thực chỉ sau khi user chọn
   Host. Cài desktop và Connect không lấy dependency này.
2. Runtime được cô lập, chỉ local/private, tất định, không dùng chung, không gắn
   với PostgreSQL global của OS và không cần PostgreSQL hay Docker/Compose có
   sẵn. Cluster không liên quan là hạ tầng external và không bao giờ được nhận
   quản lý ngầm.
3. Advanced / Server giữ PostgreSQL external do operator quản lý. Qualification
   v0.2 yêu cầu PG17 cho cả hai profile; cùng schema, migration forward có thứ
   tự và logic ứng dụng.
4. `POSTGRESQL_RUNTIME` là `SERVER_PACKAGE`, tách khỏi `SERVER_DATABASE`, config,
   secret và object data. Repair/update/remove runtime không cho phép xóa
   cluster. Gỡ desktop không tác động; gỡ software server bảo toàn state bền
   vững theo mặc định.
5. Identity artifact liên kết version/major upstream, component, platform,
   architecture, packaging version, digest, provenance, license/notice,
   inventory, compatibility và release/channel. Acquisition tuân P005/P006/P011;
   cấm nguồn không ký, mutable, không pin hoặc bypass integrity. Artifact offline
   đúng và đã verify vẫn được phép.
6. Synveil chịu trách nhiệm phát hành maintenance/security update cho runtime
   managed. Thay thế trong cùng major cần preflight, lifecycle có kiểm soát và
   health verification, không tạo lại state. Major tương lai cần đường nâng cấp
   database được kiểm chứng riêng; v0.2 không tự nâng major hoặc hứa rollback DB.
7. Chỉ được initialize sau preflight, consent Host, verify dependency và xác
   nhận ownership target. State unknown/unsupported/partial/foreign hoặc outcome
   unknown phải inspect và fail closed; không `initdb`, reset, tạo lại role hay
   drop/create mù.
8. Cần identity process hạn chế chuyên dụng và directory cluster private. UI
   thường chỉ hiện “System database”, không hiện credential, `DATABASE_URL`, port
   hay internals. P031/P033 chọn cơ chế secret/path/permission/endpoint/service.
9. Ubuntu 24.04 và Fedora 42 x86_64 là **implementation target**, chưa phải
   shipped support. Windows, macOS và Linux architecture khác là
   **NOT_YET_QUALIFIED** cho managed Personal/Home Host. Client và Advanced
   deployment không bị ảnh hưởng.
10. Khả năng backup/restore và recovery phối hợp database/object là yêu cầu
    acceptance. P036 phải chứng minh Host và đo footprint trước khi công bố
    support.

Contract đầy đủ nằm trong
[SERVER_DEPENDENCY_STRATEGY.md](../v0.2/SERVER_DEPENDENCY_STRATEGY.md). ADR này
thay thế phần distribution chưa giải quyết của ADR-019 và đóng OD-PLAT-001.

## Hệ quả (Tiếng Việt)

User thường có compatibility và ownership database tất định mà không tự quản
trị PostgreSQL. Synveil nhận chi phí package, provenance, security update,
service, repair, compatibility và support; OS không tự patch runtime private.
Host có download/footprint thực, Connect không bị ảnh hưởng. Platform support
hẹp cho tới khi có adapter và acceptance. Compose vẫn dành cho Advanced. ADR
này không tuyên bố đã provision hoặc readiness.

## Phương án khác (Tiếng Việt)

- PostgreSQL global của system: bác bỏ cho Personal/Home do drift và ambiguity
  về setting/port/credential/ownership/upgrade/uninstall.
- Bắt buộc Docker/Compose: bác bỏ ở normal mode vì thêm runtime privileged và
  lifecycle network/image/volume; vẫn giữ cho Advanced.
- Chỉ external PostgreSQL: bác bỏ ở normal vì chuyển việc quản trị cho user;
  vẫn là lựa chọn rõ ràng ở Advanced.
- SQLite/authority khác: bác bỏ vì chia schema, migration, transaction và
  correctness.

## Điều kiện di chuyển và xem xét lại (Tiếng Việt)

P031–P036 triển khai và qualify contract. Đổi managed major, bắt buộc
system/global/container, gộp runtime với data bền vững, mở rộng platform, đổi
ownership external hoặc thêm authority database thứ hai cần evidence và ADR
thay thế. Patch artifact PG17 đủ điều kiện không tự mở lại quyết định; nâng major
PostgreSQL thì có.
