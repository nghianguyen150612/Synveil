## Ownership audit

The audit covered the P037–P040 contracts and ADRs, the P036 end-to-end Host
wizard and ADR-066, desktop `Main.qml`, bridge and presentation, the client
controller/control snapshot, and client-sync runtime, cycle, host, state, and
local migration code.

The resulting ownership boundary is:

- native installers and package managers own installation progress; the
  desktop observed no reliable native completion signal;
- P036 owns detailed Host provisioning and its readiness handoff;
- P038 owns connection/profile setup;
- P039 owns authentication presentation and credential lifecycle;
- P040 owns library creation and authoritative configured-library
  confirmation;
- client-sync owns bounded cycles, scheduling, root/auth/conflict fencing, and
  the quiescent first-sync proof;
- P041 owns only the Rust product-state composition and compact rendering;
- P042 owns broad repair and recovery productization.

## Implementation

The five-stage Rust model is `app_ready`, `server_ready`, `signed_in`,
`library_ready`, and `first_sync`. It is carried through the safe control and
desktop snapshots to QML. Stage state is finite and semantic; QML does not
parse runtime strings, run a sync loop, or own persistence.

Migration 0008 adds the bounded `first_sync_completed` evidence bit to local
replicas. New bindings begin false. The host wraps the existing cycle with a
small evidence adapter; the runtime calls it only after `is_idle()` and after
confirming that no pending follow-up wake exists. Legacy replicas default true
so existing users remain on normal routing.

The bridge applies the existing latest-value ordering rules and rejects an
older connection generation or revision. The page is visible only while a
newly configured library still lacks first-sync evidence. A later ordinary
sync therefore does not reopen the first-run page.

No installer telemetry, native installer replacement, percentage, timer,
second scheduler, repair console, reset action, root relocation, telemetry, or
remote progress service was added.

## Focused tests and validation

Added deterministic coverage includes setup evidence, Welcome/connection/
authentication/library routing, library creation versus first-sync evidence,
running/scheduled/progress/backoff states, true idle, follow-up wake fencing,
stale snapshots, revision/generation ordering, pause, root/auth/conflict/fatal
action-required states, durable marker behavior, accessibility identifiers,
bounded copy, and privacy terminology.

The focused workflow separates client-sync runtime/sync tests, client
controller tests, desktop presentation/QML checks, docs/static validation,
formatting, and quality checks. Offscreen checks are not represented as native
GUI acceptance, and no native package-manager progress integration is claimed.

Environment-dependent validation is recorded in the final handoff. This
manifest intentionally contains no commit SHA generated by the commit itself.
