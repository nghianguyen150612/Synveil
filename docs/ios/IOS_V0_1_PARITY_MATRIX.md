## Audit disposition and traceability

**Baseline-critical gap:** PAR-03 and PAR-04 (CAP-13), labeled server profiles and multi-profile switching. Android supports multiple persisted profiles; the iOS app currently supports one endpoint/session. These rows remain **BLOCKED** and cannot be counted as parity until implemented or an owner-approved product-scope revision explicitly changes release requirements.

**Device qualification:** Simulator tests prove iOS implementation behavior but not signed iPhone operation. Keychain protection, actual BGAppRefresh delivery, accessibility, PhotoKit permission, secure file attributes and signed archive acceptance require P060 physical-device evidence or release-blocking disposition.

**Security boundaries:** PAR-38 remains OFF under the P051 redirect rule. PAR-39 (P055) is unmerged. PAR-41 must not convert a verified uploaded FileVersion into PhotoAsset/Live Photo binding or retained BackupSnapshot proof. PhotoKit source disappearance must never cause remote deletion.

**Source validation:** 4 iOS CI checks passed on the source commit `373ae476...` (runs 39093259832, 39093259817, 39093259786, 39093259808); native simulator: 2,024 passed, 2 skipped, 0 failed. P059 final-head CI evidence belongs in `PROMPT059_MANIFEST.md` after completion. Android release evidence from `clients/android/ANDROID_PROGRESS.md` and `clients/android/RELEASE.md` is historical; no current Android connected-device execution is asserted.
